# Flutter 性能优化与平台通道

当 Flutter 应用功能逐渐复杂，性能问题往往从幕后走向台前：列表滑动掉帧、图片加载卡顿、大量数据计算阻塞 UI 线程。本章将从**性能分析**、**优化策略**和**原生通信**三个维度，系统讲解如何打造流畅且高效的 Flutter 应用。

## 性能分析工具

Flutter 提供了强大的性能调试工具链，核心是两个：Flutter DevTools 和性能 Overlay。

### Flutter Performance Overlay

在 `MaterialApp` 或 `CupertinoApp` 中开启：

```dart
class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      // 显示性能图层（仅 Debug 模式）
      showPerformanceOverlay: true,
      home: const HomePage(),
    );
  }
}
```

性能图层在屏幕顶部显示两条水平线：
- **绿色线**：UI 线程耗时（Dart 代码执行 + Widget 构建）
- **蓝色线**：Raster 线程耗时（GPU 渲染）

每帧 16.67ms（60fps）对应的线高是基准。如果柱状图超过水平线，说明该帧超时，用户会感知到掉帧。

### Flutter DevTools

通过命令行启动：

```bash
flutter pub global activate devtools
flutter pub global run devtools
```

或在 IDE 中直接打开。DevTools 提供多个面板：

| 面板 | 用途 |
|------|------|
| **Flutter Inspector** | Widget 树检查、布局边界可视化 |
| **Performance** | 逐帧分析，标记耗时的 build/rebuild |
| **CPU Profiler** | Dart 代码的 CPU 采样分析 |
| **Memory** | 内存分配追踪，检测泄漏 |
| **Network** | HTTP 请求拦截与查看 |
| **Logging** | 日志过滤与搜索 |

### Widget Rebuild 分析

在 DevTools 中开启 **Track Widget Builds**，可以精确看到哪些 Widget 被重建了：

```dart
// 在代码中临时添加，标记需要追踪的 Widget
class ExpensiveWidget extends StatelessWidget {
  const ExpensiveWidget({super.key});

  @override
  Widget build(BuildContext context) {
    // 添加 debug 标记，便于 DevTools 定位
    return const Placeholder();
  }
}
```

关键原则：**重建次数越少，性能越好**。如果一个纯展示 Widget 的数据未变却被反复重建，说明存在不必要的依赖。

## Widget 重建优化

### const 构造函数

`const` Widget 在父 Widget 重建时不会重新创建，是最简单的优化手段：

```dart
// ❌ 每次父 Widget rebuild 都会创建新的 Text
Text('Static Title')

// ✅ const 构造函数，复用实例
const Text('Static Title')

// ❌ 非 const 列表
Column(
  children: [
    Text('A'),  // 每次重建都 new
    Text('B'),
  ],
)

// ✅ const 列表
const Column(
  children: [
    Text('A'),  // 编译时常量，不再重建
    Text('B'),
  ],
)
```

### const 构造函数的最佳实践

```dart
class OptimizedPage extends StatelessWidget {
  const OptimizedPage({super.key}); // Widget 本身也用 const

  @override
  Widget build(BuildContext context) {
    return const Scaffold(
      appBar: PreferredSize(
        preferredSize: Size.fromHeight(56),
        child: MyAppBar(), // 如果 MyAppBar 是 const 构造，这里也可 const
      ),
      body: Column(
        children: [
          // 静态部分全部 const
          const HeaderWidget(),
          const Divider(),
          // 只有动态部分不用 const
          DynamicContent(),
        ],
      ),
    );
  }
}
```

### 精细化重建：ValueListenableBuilder

当只需要监听一个值的变化时，用 `ValueListenableBuilder` 替代 `setState`，只重建必要部分：

```dart
class CounterWithValueListenable extends StatefulWidget {
  const CounterWithValueListenable({super.key});

  @override
  State<CounterWithValueListenable> createState() => _CounterState();
}

class _CounterState extends State<CounterWithValueListenable> {
  final _counter = ValueNotifier<int>(0);

  @override
  void dispose() {
    _counter.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Column(
        children: [
          // 静态部分，不随计数器变化重建
          const Text('Counter App'),
          const SizedBox(height: 20),

          // 只有这里会重建
          ValueListenableBuilder<int>(
            valueListenable: _counter,
            builder: (context, value, child) {
              return Text(
                '$value',
                style: const TextStyle(fontSize: 48),
              );
            },
          ),
        ],
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () => _counter.value++,
        child: const Icon(Icons.add),
      ),
    );
  }
}
```

### 列表优化

```dart
class OptimizedList extends StatelessWidget {
  final List<String> items;
  const OptimizedList({super.key, required this.items});

  @override
  Widget build(BuildContext context) {
    return ListView.builder(
      // itemCount 必须提供，ListView 才知道有多少项
      itemCount: items.length,
      // itemExtent 能大幅提升性能：提前知道每行高度
      itemExtent: 72,
      // cacheExtent 控制屏幕外预渲染区域
      cacheExtent: 200,
      itemBuilder: (context, index) {
        return ListTile(
          // key 帮助 Flutter 识别同一数据项，避免错位重建
          key: ValueKey(items[index]),
          title: Text(items[index]),
        );
      },
    );
  }
}
```

对于超长列表，使用 `CustomScrollView` + `SliverList` 可以获得更精细的滚动控制：

```dart
CustomScrollView(
  slivers: [
    SliverAppBar(/* ... */),
    SliverList.builder(
      itemCount: 10000,
      itemBuilder: (context, index) {
        return const ListTile(title: Text('Item'));
      },
    ),
  ],
)
```

### RepaintBoundary 隔离重绘

当一个 Widget 需要频繁重绘（如动画），但其父级不需要时，用 `RepaintBoundary` 包裹可以隔离重绘范围：

```dart
Column(
  children: [
    const StaticHeader(), // 不需要重绘
    RepaintBoundary(
      child: AnimatedWidgetThatUpdatesOften(),
    ),
    const StaticFooter(), // 不需要重绘
  ],
)
```

## Isolate 与并发

Flutter 是单线程事件循环模型，Dart 代码默认运行在 UI Isolate 上。耗时的计算任务会阻塞帧渲染，应放到独立的 **Isolate** 中执行。

### 基础 Isolate

```dart
import 'dart:isolate';

// 在 Isolate 中执行的函数必须是顶层函数或静态方法
void _heavyComputation(SendPort sendPort) {
  int result = 0;
  for (int i = 0; i < 100000000; i++) {
    result += i;
  }
  // 将结果发回主 Isolate
  sendPort.send(result);
}

Future<int> runHeavyComputation() async {
  final receivePort = ReceivePort();

  // 创建新 Isolate
  await Isolate.spawn(_heavyComputation, receivePort.sendPort);

  // 等待结果（异步，不阻塞 UI）
  final result = await receivePort.first as int;
  receivePort.close();

  return result;
}

// 使用
class ComputeDemo extends StatefulWidget {
  const ComputeDemo({super.key});

  @override
  State<ComputeDemo> createState() => _ComputeDemoState();
}

class _ComputeDemoState extends State<ComputeDemo> {
  int? _result;

  Future<void> _compute() async {
    final result = await runHeavyComputation();
    setState(() => _result = result);
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        ElevatedButton(
          onPressed: _compute,
          child: const Text('开始计算'),
        ),
        if (_result != null) Text('结果: $_result'),
      ],
    );
  }
}
```

### 使用 compute 函数简化

对于简单的单次计算，Flutter 提供了更便捷的 `compute` 函数：

```dart
import 'package:flutter/foundation.dart';

// 解析大 JSON
Future<List<Item>> parseItems(String jsonString) async {
  return compute(_parseItemsInIsolate, jsonString);
}

// 这个函数在后台 Isolate 中执行
List<Item> _parseItemsInIsolate(String jsonString) {
  final decoded = jsonDecode(jsonString) as List;
  return decoded.map((e) => Item.fromJson(e)).toList();
}
```

### Isolate 间通信模式

```dart
class IsolateWorker {
  Isolate? _isolate;
  late SendPort _sendPort;
  final _receivePort = ReceivePort();
  final _responseController = StreamController<dynamic>.broadcast();

  Future<void> start() async {
    _isolate = await Isolate.spawn(
      _workerEntry,
      _receivePort.sendPort,
    );

    // 获取工作 Isolate 的 SendPort
    _sendPort = await _receivePort.first;

    // 监听后续消息
    _receivePort.listen((message) {
      _responseController.add(message);
    });
  }

  void sendTask(String task, dynamic data) {
    _sendPort.send({'task': task, 'data': data});
  }

  Stream<dynamic> get responses => _responseController.stream;

  void dispose() {
    _isolate?.kill();
    _receivePort.close();
    _responseController.close();
  }

  static void _workerEntry(SendPort mainSendPort) {
    final workerReceivePort = ReceivePort();
    mainSendPort.send(workerReceivePort.sendPort);

    workerReceivePort.listen((message) {
      final task = message['task'] as String;
      final data = message['data'];

      switch (task) {
        case 'parse':
          final result = jsonDecode(data);
          mainSendPort.send(result);
        case 'process':
          final result = heavyProcessing(data);
          mainSendPort.send(result);
      }
    });
  }
}
```

## Platform Channel：与原生通信

当 Flutter 的 Dart 层无法满足需求时（如调用系统 API、使用原生 SDK），需要通过 **Platform Channel** 与原生代码通信。

### MethodChannel：同步调用

```dart
import 'package:flutter/services.dart';

// Dart 端
class BatteryService {
  static const _channel = MethodChannel('com.example/battery');

  static Future<int> getBatteryLevel() async {
    try {
      final level = await _channel.invokeMethod<int>('getBatteryLevel');
      return level ?? -1;
    } on PlatformException catch (e) {
      throw Exception('获取电量失败: ${e.message}');
    }
  }
}
```

### Android 端实现

```kotlin
// android/app/src/main/kotlin/.../MainActivity.kt
import io.flutter.embedding.android.FlutterActivity
import io.flutter.embedding.engine.FlutterEngine
import io.flutter.plugin.common.MethodChannel
import android.content.Context
import android.content.Intent
import android.content.IntentFilter
import android.os.BatteryManager

class MainActivity : FlutterActivity() {
    private val CHANNEL = "com.example/battery"

    override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
        super.configureFlutterEngine(flutterEngine)

        MethodChannel(flutterEngine.dartExecutor.binaryMessenger, CHANNEL)
            .setMethodCallHandler { call, result ->
                when (call.method) {
                    "getBatteryLevel" -> {
                        val level = getBatteryLevel()
                        result.success(level)
                    }
                    else -> result.notImplemented()
                }
            }
    }

    private fun getBatteryLevel(): Int {
        val batteryStatus = registerReceiver(null,
            IntentFilter(Intent.ACTION_BATTERY_CHANGED))
        val level = batteryStatus?.getIntExtra(BatteryManager.EXTRA_LEVEL, -1) ?: -1
        val scale = batteryStatus?.getIntExtra(BatteryManager.EXTRA_SCALE, -1) ?: -1
        return (level * 100 / scale)
    }
}
```

### iOS 端实现

```swift
// ios/Runner/AppDelegate.swift
import Flutter
import UIKit

@main
@objc class AppDelegate: FlutterAppDelegate {
    override func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        let controller = window?.rootViewController as! FlutterViewController
        let batteryChannel = FlutterMethodChannel(
            name: "com.example/battery",
            binaryMessenger: controller.binaryMessenger
        )

        batteryChannel.setMethodCallHandler { call, result in
            switch call.method {
            case "getBatteryLevel":
                let level = UIDevice.current.batteryLevel
                result(Int(level * 100))
            default:
                result(FlutterMethodNotImplemented)
            }
        }

        UIDevice.current.isBatteryMonitoringEnabled = true
        GeneratedPluginRegistrant.register(with: self)
        return super.application(application, didFinishLaunchingWithOptions: launchOptions)
    }
}
```

### EventChannel：持续数据流

当需要持续接收原生端的数据（如传感器数据、蓝牙状态变化），使用 **EventChannel**：

```dart
// Dart 端
class SensorService {
  static const _eventChannel = EventChannel('com.example/sensor');

  static Stream<double> get accelerometerStream {
    return _eventChannel
        .receiveBroadcastStream()
        .map((event) => event as double);
  }
}

// 使用
StreamSubscription? _subscription;

void startListening() {
  _subscription = SensorService.accelerometerStream.listen((value) {
    print('传感器数据: $value');
  });
}

void stopListening() {
  _subscription?.cancel();
}
```

### BasicMessageChannel：编解码通信

当需要传递自定义数据类型时，使用 **BasicMessageChannel** 配合自定义编解码器：

```dart
// Dart 端
class BinaryMessageService {
  static const _channel = BasicMessageChannel<dynamic>(
    'com.example/binary',
    StandardMessageCodec(),
  );

  static Future<dynamic> sendMessage(Map<String, dynamic> message) async {
    final response = await _channel.send(message);
    return response;
  }
}
```

### Pigeon：类型安全的平台通道

Google 推出的 **Pigeon** 工具可以从 Dart 接口定义自动生成双端的类型安全通信代码，避免手写 Platform Channel 的样板代码：

```yaml
dependencies:
  pigeon: ^22.0.0
```

```dart
// pigeons/messages.dart
import 'package:pigeon/pigeon.dart';

@ConfigurePigeon(PigeonOptions(
  dartOut: 'lib/messages.g.dart',
  kotlinOut: 'android/app/src/main/kotlin/.../Messages.g.kt',
  swiftOut: 'ios/Runner/Messages.g.swift',
))

@HostApi()
abstract class BatteryApi {
  int getBatteryLevel();
}

@FlutterApi()
abstract class BatteryCallback {
  void onBatteryLevelChanged(int level);
}
```

运行 `flutter pub run pigeon --input pigeons/messages.dart` 即可生成类型安全的双端代码。

## 综合性能优化检查清单

```dart
// 1. 使用 const 构造函数
const MyWidget()

// 2. 使用 ValueListenableBuilder 替代 setState
ValueListenableBuilder(valueListenable: counter, builder: ...)

// 3. 列表使用 builder 构造
ListView.builder(itemCount: count, itemBuilder: ...)

// 4. 指定 itemExtent 提升滚动性能
ListView.builder(itemExtent: 72, ...)

// 5. 图片指定缓存尺寸
Image.network(url, cacheWidth: 400)

// 6. 耗时计算放入 Isolate
await compute(heavyTask, data)

// 7. 使用 RepaintBoundary 隔离频繁重绘区域
RepaintBoundary(child: AnimatedWidget())

// 8. 避免在 build 中创建对象
// ❌
Widget build(context) {
  final formatter = DateFormat('yyyy-MM-dd'); // 每次重建都创建
  return Text(formatter.format(date));
}

// ✅
final _formatter = DateFormat('yyyy-MM-dd'); // 作为类字段
Widget build(context) {
  return Text(_formatter.format(date));
}

// 9. 使用 Selector 替代 Consumer 做精细依赖
Selector<MyModel, int>(
  selector: (context, model) => model.count,
  builder: (context, count, child) => Text('$count'),
)
```

## 总结

| 优化方向 | 关键策略 |
|---------|---------|
| 减少重建 | `const` 构造函数、`ValueListenableBuilder`、`Selector` |
| 列表优化 | `ListView.builder`、`itemExtent`、`cacheExtent` |
| 图片优化 | 指定 `cacheWidth/cacheHeight`、渐显加载 |
| 隔离重绘 | `RepaintBoundary` |
| 异步计算 | `compute()`、`Isolate.spawn` |
| 原生通信 | `MethodChannel`、`EventChannel`、Pigeon |

性能优化不是一次性工作，而是一个持续的过程。养成使用 DevTools 分析的习惯，配合上述策略，可以系统性地提升 Flutter 应用的流畅度。
